# 修复拼图碎片错误放置问题计划

## 1. 现状分析
当前在 `usePuzzleGame.ts` 的 `placePiece` 函数中，系统仅检查目标格子是否被占据，并没有校验用户拖拽的碎片其 `correctRow` 和 `correctCol` 是否与目标格子的 `row` 和 `col` 匹配。这导致了用户可以将拼图放在任意位置，最终拼图无法完成且游戏卡死。

## 2. 目标与验收标准
- **目标**：实现严格的位置校验，当拼图放置在错误位置时，拒绝放置并给予用户错误提示，同时碎片自动返回候选区。
- **验收标准**：
  1. 用户将拼图拖到错误的格子上松手时，拼图会飞回候选区（或原位置）。
  2. 屏幕上方弹出“错误，再试试”的提示信息，并在1秒后自动消失。
  3. 用户将拼图拖到正确的格子上时，拼图正常吸附并记录进度。

## 3. 拟修改内容

### 3.1 修改 `src/hooks/usePuzzleGame.ts`
- **目标**：在 `placePiece` 方法中增加位置校验逻辑。
- **改动细节**：
  - 在放置前增加条件判断：如果 `piece.correctRow !== row || piece.correctCol !== col`，则直接返回 `{ type: 'fail', reason: 'wrong-position' }`。
  - 由于做了严格校验，目标格子理论上只可能是空或者碎片自己，因此可以简化原有的交换（swap）逻辑，直接拒绝异常占据。

### 3.2 修改 `src/components/puzzle/PuzzleGame.tsx`
- **目标**：处理放置失败的返回值，并增加 Toast 错误提示状态。
- **改动细节**：
  - 新增状态 `const [toastMessage, setToastMessage] = useState<string | null>(null)`。
  - 在 `handleDragEnd` 中，如果 `result.type === 'fail'` 且 `result.reason === 'wrong-position'`，则设置 `toastMessage` 为 `"错误，再试试"`，并通过 `setTimeout` 在 1 秒后清除。
  - 在渲染区域（如 `PuzzleBoard` 的上方）新增一个绝对定位的 Toast 提示框，展示 `toastMessage`。结合已有的 `animate-fade-up` 动画使其显示更加平滑。

## 4. 假设与决策
- **决策**：错误提示将以浮动 Toast 的形式显示在页面顶部居中位置，不阻挡用户的继续操作。
- **决策**：放弃拼图间的“交换”功能（原来的 swap 逻辑），因为强制要求放在正确位置后，用户不可能将两个拼图放在彼此错误的位置上，每次拖拽都必须对准最终的正确位置。

## 5. 验证步骤
1. 启动项目，进入拼图游戏。
2. 故意将某块拼图拖到明显不属于它的格子上。
3. 验证：该碎片飞回下方的候选区。
4. 验证：屏幕上方出现“错误，再试试”的提示，并在 1 秒后消失。
5. 将拼图拖到正确的格子上，验证可以正常吸附且没有报错。
